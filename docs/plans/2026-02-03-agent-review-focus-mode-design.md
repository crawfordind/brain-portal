# Agent Review Focus Mode - Design Document

**Date:** 2026-02-03
**Status:** Approved
**Goal:** Transform agent output review from raw markdown inspection to efficient manager approval workflow

## Problem Statement

The current agent review modal (`agent-review-panel.tsx`) has UX issues that slow down the approval workflow:

1. **Raw markdown display** - Output shows unformatted markdown text, making it hard to read and evaluate quality
2. **Split attention** - Side-by-side layout forces constant context switching between request and output
3. **Unclear workflow** - All actions (approve, revise, reject) have equal visual weight, no clear "happy path"
4. **Missing quick actions** - No fast way to save approved work as notes or integrate into knowledge base

## Target User Experience

**Manager Approval Workflow:**
- Review formatted, beautiful output in focus mode (like reading a document)
- Quickly iterate with inline revision requests
- One-click approve & save to notes when satisfied
- Clear visual hierarchy guiding the workflow

## Design Solution

### 1. Core Concept: Focus Mode Review

**Full-width formatted output** takes center stage:
- Properly rendered markdown using `marked` library (already installed)
- Beautiful typography with prose styling
- Code blocks, lists, headings formatted correctly
- Minimal distractions during review

**Original prompt accessible but hidden:**
- Small collapsible button: "View Original Prompt"
- Expands to show request context when needed
- Doesn't compete for attention during review

**Floating action toolbar:**
- Sticky bottom bar with clear action hierarchy
- Primary actions: Request Revision → Approve & Save
- Secondary: Copy, View Context, More options

**New Components:**

2. `components/agents/agent-review-focus-panel.tsx`
   - Main focus mode interface
   - Replaces `agent-review-panel.tsx`

3. `components/agents/save-to-note-dialog.tsx`
   - Quick dialog for approve & save
   - Note title, project, linking options

### 3. Two-Phase Action Workflow

**Phase 1: Iteration Mode** (status: `awaiting_review`)

```
┌────────────────────────────────────────────────┐
│ [Textarea: "What would you like changed?"]     │
│ [Request Revision (2/5)] [Copy] [⋮ More]       │
└────────────────────────────────────────────────┘
```

- Inline feedback textarea (auto-expands)
- "Request Revision" disabled until feedback entered
- Shows revision count
- After submit, task returns to `processing`

**Phase 2: Approval Mode** (when satisfied)

```
┌────────────────────────────────────────────────┐
│ [✓ Approve & Save to Note] [Request Revision]  │
│ [× Reject]                                      │
└────────────────────────────────────────────────┘
```

- Primary action: "Approve & Save to Note"
  - Opens dialog with note title, project selector
  - Links to task and context notes
  - Creates note via new API endpoint
- Secondary: Request revision (if needed)
- Tertiary: Reject with confirmation

### 4. Markdown Rendering

**Typography Stack:**
```tsx
<div className="prose prose-slate dark:prose-invert max-w-none">
  {/* Rendered HTML from marked */}
</div>
```

**Styling:**
- Use existing Tailwind prose classes
- Code blocks: `bg-muted`, monospace font
- Headings: proper hierarchy (h1-h6)
- Lists: indented, styled bullets
- Blockquotes: left border accent
- Links: clickable, `rel="noopener noreferrer"`
- Tables: bordered, striped rows

**Security:**
- Configure `marked` with safe options
- Sanitize HTML to prevent XSS
- External links open in new tab

### 5. API Changes

**New Endpoint:**

`POST /api/agent-tasks/[id]/save-as-note`

**Request:**
```json
{
  "title": "Note title",
  "projectId": "optional-project-id",
  "linkContextNotes": true,
  "linkTask": true
}
```

**Note Format:**
```markdown
[Agent output content]

---
*Generated by [Agent Name] using [Model]*
*Created: [timestamp]*
*Task: [link to task]*
*Context: [links to reference notes]*
```

**Existing Endpoints (no changes):**
- `GET /api/agent-tasks/[id]` - fetch task + outputs
- `POST /api/agent-tasks/[id]/revise` - request revision
- `POST /api/agent-tasks/[id]/approve` - mark approved
- `POST /api/agent-tasks/[id]/reject` - reject task

### 6. Polish & UX Details

**Original Prompt Reveal:**
- Pill button: "View Original Prompt ↓"
- Smooth expand animation (framer-motion)
- Muted card background
- Collapse with "Hide Prompt ↑"

**Status Indicators:**
- Badge showing task status
- Version counter: "Version 3 of 5"
- Agent avatar/icon in header

**Floating Action Bar:**
- Sticky bottom position
- Backdrop blur effect
- Shadow for elevation
- Smooth state transitions

**Keyboard Shortcuts:**
- `Cmd/Ctrl + Enter` - Request revision
- `Cmd/Ctrl + S` - Approve & save
- `Cmd/Ctrl + C` - Copy output
- `Escape` - Close panel

**Loading States:**
- Skeleton for markdown while fetching
- Disabled buttons during API calls
- Toast notifications (sonner) for feedback

**Empty/Error States:**
- "Processing..." when no output yet
- Error message with retry
- Max revisions warning

### 7. Database Schema

**No changes needed!** Existing schema supports everything:
- `agent_tasks.description` - original prompt ✓
- `agent_task_outputs.content` - markdown output ✓
- `agent_task_feedback` - revision history ✓
- Existing note linking patterns ✓
